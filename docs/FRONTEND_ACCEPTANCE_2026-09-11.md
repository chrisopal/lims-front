# LIMS 完整交互前端验收（2026-09-11）

## 完成口径

沿用用户确认的“完整交互前端”：既有菜单有可操作页面，配置写入后能刷新读回；场景发布、实验室启用、委托、工作项、审核、报告共用本地数据。所有后台能力保持前端模拟边界。

## 验证方法

- 领域测试断言本地存储、状态转换、冻结快照、幂等、冲突、损坏存储和读写失败。
- 真实 Chromium 验证操作后刷新回读，读取下载文件内容，不以提示消息代替业务证据。
- 32 个页面覆盖 1366、1440、1920、390 宽度；流程与目录操作覆盖桌面和手机。
- 审核退回曾发现保存期间意见被清空，已修复；新增回归要求再次加载后保留意见，并完成返工、再审核与报告。
- 生产构建更新时产生过资源 404，最终验收使用固定构建重新运行，避免把重建干扰计入产品结果。

最终结果以仓库 `qa-artifacts/*report.json`、`catalog-browser.json`、`scenario-browser.json` 和 `session-browser.json` 为准；CI 上传证据包。复跑命令见 `FRONTEND_INTERACTIVE_V2_2.md`。

## 明确边界

- 浏览器数据属于当前浏览器，不提供多用户服务器持久化；演示身份不构成正式鉴权。
- 配置可保存并参与发布快照；工作流执行为顺序人工工作项模拟。并行网关、定时器、仪器连接、AI 与外部系统执行由后端实现。
- 报告展示实际本地委托、检测项、节点记录、审核记录及冻结模板引用。当前提供统一 HTML 预览，不是任意排版模板引擎、正式检测结论或电子签章。
- 生产构建存在 Element Plus 共享资源块超过 500 kB 的提示，构建成功；尚未进行正式网络条件下的性能基准测试。
