# Figma Make AI Prompt · LIMS v2.0

> 下面整段可以直接复制给 Figma Make AI。目标是生成一套可交互、高保真的桌面端企业 LIMS 原型。重点不是普通后台 CRUD，而是把 v2 的“Scenario Pack 生命周期驱动 + 可执行 Workflow + 专业节点工作台”体现出来。

```text
请设计一套桌面 Web 端高保真企业产品原型，产品名称暂定：

Laboratory Operations Platform
副标题：Composable AI-Native LIMS

这是一个面向企业内部实验室、第三方检测实验室以及多行业检测场景的“可组合实验室运营平台”。

产品核心不是传统固定流程 LIMS，而是：

Capability Module（代码能力）
+ Reusable Asset（检测项、法规标准、方法、报告等业务资产）
→ Scenario Pack（场景包）
→ Guided Configuration
→ Validate
→ Publish
→ Immutable Scenario Snapshot
→ Runtime

必须让用户从 UI 中直观看懂：

1. 场景包是业务配置和发布的核心对象；
2. 场景包通过引导式生命周期完成配置，不是固定的一堆 Tab；
3. 法律法规、标准、检测项、方法、报告模板等仍有独立专业管理页面，但可以从场景包上下文进入、绑定并返回；
4. 检测流程不是静态流程图，节点对应真实的后台执行能力和前端专业工作台；
5. 发布后的场景版本不可直接编辑，修改必须创建新版本；
6. 运行态新建委托/申请时直接选择“已发布并激活的检测场景”，系统根据场景快照加载对应流程、表单、检测项和工作台；
7. AI 是流程中的一个业务能力，不是一个悬浮聊天机器人。

三、核心产品概念
==================================================

A. Scenario Pack 场景包

一个场景包代表一个完整的检测业务场景，例如：
- 第三方食品理化检测
- 食品微生物检测
- 环境水质现场采样与实验室检测
- 企业内部来料理化检验
- 企业内部几何量 / 三坐标检测
- 客户现场尺寸检测
- 新能源电池循环寿命测试

场景包包括：
- 业务模式
- 检测对象
- 检测项
- 法律法规 / 标准
- 检测方法
- 限值 / 公式
- 检测流程
- 动态表单
- 资源与人员资质
- 报告模板
- AI Skill

B. Reusable Asset 可复用业务资产

这些资产有独立管理菜单：
- Test Item
- Regulation / Standard
- Method
- Limit Rule
- Formula
- Form Schema
- Report Template
- Qualification Policy
- AI Skill

场景包只是引用和绑定，不要把公共资产复制进每个场景。

C. Capability / Node Type

流程设计器中的节点来自平台能力注册，例如：
- 委托受理 REQUEST_ACCEPTANCE
- 采样方案 SAMPLING_PLAN
- 现场采样 FIELD_SAMPLING
- 收样 SAMPLE_RECEIPT
- 样品前处理 SAMPLE_PREPARATION
- 实验室检测 LAB_TEST_EXECUTION
- 客户现场检测 ONSITE_INSPECTION
- 几何量测量 METROLOGY_MEASUREMENT
- 技术审核 TECHNICAL_REVIEW
- 报告生成 REPORT_GENERATION
- 报告审核 REPORT_REVIEW
- 报告签发 REPORT_RELEASE
- Rule Node
- AI Node
- Integration Node

每一个业务节点都应该让人感觉它“可以真正执行”，而不是只是一张流程图。
```
